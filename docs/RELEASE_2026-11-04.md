# Release 2026-11-04: invoices with payment details

How to put live what was merged to `main` on 4 November 2026. The release is still one command, `deploy.sh`
([deploy/README.md §6](../deploy/README.md#6-releasing-an-update)). This page covers what is new, the one database change, the
set-up AQUA HUB needs afterwards, and how to roll back. Troubleshooting is unchanged from
[RELEASE_2026-11-03.md §6](RELEASE_2026-11-03.md#6-if-something-goes-wrong).

Allow **30 minutes** (45 if the 3 November release was never run), outside AQUA HUB's opening hours. The API is down for a few seconds
during the restart.

---

## 1. What is in this release

| Repo | Change | What users notice |
|---|---|---|
| Backend | **Invoice payment details**: bank name and branch, account name and number, the bank's paybill, a Buy Goods till, a send-money phone, days to pay and a note, saved on the business (`PUT /businesses/current/invoice-settings`, `Businesses.Update`); optional `invoice` when registering a business | Through the frontend below |
| Frontend | **Invoices for credit sales**: *Invoice* on a credit sale (that sale, less what is paid) and on a customer's page (every unpaid credit sale, oldest first); A4, logo at the top, stamped PAID or OVERDUE; **Print invoice** and **Download PDF** | New *Invoice* buttons |
| Frontend | **Settings → Invoices**: the *Send payment to* card with a live preview; also in the invoice dialog and as an optional step when registering a business | New settings section |
| Frontend | Credit-sale receipts (80 mm and A4) carry *Send payment to*; paid sales never do | Credit receipts are slightly longer |
| Frontend | **AQUA HUB logo** shipped with the app (`/tenants/aqua-hub/logo.png`); the business profile's *Logo link* takes such a path and shows a preview | Logo on invoices, sign-in screen and sidebar once set (§5) |

Target commits: backend **`de48ea6`**, frontend **`4f065f2`**. Both are pushed.

**If the 3 November release was never run**, this release carries it too: receipt printing fixes and auto-print, dashboard
drilldowns, *Not completed* sales, the Electrical sector. Then also do the till set-up in
[RELEASE_2026-11-03.md §5](RELEASE_2026-11-03.md#5-aqua-hubs-till-receipt-printing) and its checks in §4.

**Not in this release:** the uncommitted minimart and pharmacy sector defaults (deliveries, tray, bale and carton units, `PKG` and
`REF` expense categories for new minimarts, the sachet unit for new pharmacies) and the minimart and chemist demo material.
`deploy.sh` pulls `main` only. They affect only businesses registered after they ship, so they can follow in a later release.
Nor the **liquor store** work ([DEMO_LIQUOR_STORE.md](DEMO_LIQUOR_STORE.md) §6): the Liquor sector, age-restricted products with the age
check at the till, selling hours and the age-check register. It brings a migration (`LiquorAgeRestrictedSales`) and a frontend
change, so it needs a release of its own. It changes nothing for AQUA HUB until a product is marked age-restricted.

### Database: one migration

`20261104055948_BusinessInvoicePaymentDetails` adds nine **nullable** columns to `Businesses`. Nothing is copied or changed, and no
existing business gets values: invoices print no payment block until someone fills in *Settings → Invoices*. The previous code
ignores these columns, so a rollback is still code only (§7).

**Nothing else changes for AQUA HUB's data.** eTIMS stays **off** for AQUA HUB: do not switch it on as part of this release.

## 2. Before you start

- [ ] Find out from the server (§3) whether the 3 November release ran: live backend `7a49290` means yes; `335bba8` means no.
- [ ] Tell AQUA HUB when you will release, and that the till will be unavailable for a minute.
- [ ] Ask AQUA HUB's owner for the details to print under *Send payment to*: bank, branch, account name and number, the bank's paybill
      and account, Buy Goods till, M-Pesa phone, days to pay. Do not reuse the M-Pesa till or paybill set in the business profile
      unless the owner says it is the same one.
- [ ] Have to hand: SSH access to the server, your Super User sign-in, and AQUA HUB's owner or manager for §5.

## 3. Release

```bash
ssh deploy@<server>
cd /home/deploy/ultimatepos
git -C backend log -1 --oneline     # note this commit (7a49290 or 335bba8)
git -C frontend log -1 --oneline    # and this one (b7d1df1 or 0ec8615)
df -h /                             # at least ~5 GB free

cd backend/deploy
./pos.sh exec -T db sh -c 'psql -U "$POSTGRES_USER" "$POSTGRES_DB" -tc "select max(\"MigrationId\") from \"__EFMigrationsHistory\""'
# expect 20261027112110_BusinessEtimsEnabled
```

Then release:

```bash
/home/deploy/ultimatepos/backend/deploy/deploy.sh
```

| Step | Expect |
|---|---|
| 1/5 Backing up the database | "dumped … to …". **Note the file name**: this release changes the schema |
| 2/5 Pulling the latest main | backend, frontend and website fast-forward |
| 3/5 Building the images | 5–10 minutes |
| 4/5 Updating the database | **"Applying 1 migration(s): 20261104055948_BusinessInvoicePaymentDetails"**. More than one means the database was further behind: read the names |
| 5/5 Restarting | "Released. https://… is up." |

## 5. AQUA HUB set-up, with the owner or manager

1. **Logo.** *Business profile* → *Logo link*: `/tenants/aqua-hub/logo.png` (skip if a logo is already set and looks right). The
   preview shows it. Save. The next sign-in screen shows it after one sign-in on that device.
2. **Payment details.** *Settings → Invoices* → *Send payment to*: enter what the owner gave you (§2). Only filled lines print; with
   no bank, till or phone the block is left off. Check the preview, then Save. This needs `Businesses.Update` (the owner has it);
   others see it read-only.
3. **Test an invoice.** Open a customer with unpaid credit sales → **Invoice**: every unpaid sale is listed, the balance matches the
   customer's balance, the logo and *Send payment to* show. **Download PDF** and open the file. **Print invoice** prints A4 (choose
   an A4 printer or *Save as PDF*, not the XP-T80A).
4. **Test a credit receipt.** Reprint a recent credit sale's receipt on the till: *Send payment to* appears at the bottom, still on
   one strip.

If the customer's invoice button is missing, the user lacks `CustomerReports.View`: the account invoice needs the aging report. A
single sale's invoice still opens, showing its whole total as due.

## 6. If something goes wrong

As in [RELEASE_2026-11-03.md §6](RELEASE_2026-11-03.md#6-if-something-goes-wrong). One addition: if step 4/5 fails, the API was not
restarted and the old version is still serving. Do not retry blindly; read the migrate output first.

## 7. Rolling back

Code only. The added columns are nullable and the old code does not read them, so leave the database as it is:

```bash
cd /home/deploy/ultimatepos
git -C backend checkout <backend commit noted in §3>
git -C frontend checkout <frontend commit noted in §3>
cd backend/deploy
./pos.sh build api && ./pos.sh build web
./pos.sh up -d
```

Put both back on `main` before the next `deploy.sh`. Payment details saved in the meantime stay in the database and reappear when
the release goes live again. Restore the step 1 backup only if data went wrong, which this release cannot cause by itself.
